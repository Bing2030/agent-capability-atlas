01 / SCOPE & READING GUIDE

这不是岗位分类学，而是工程责任地图

本图的定位：把「证据、全景、行动」放在同一张图上。能力按 9 个域 + 1 个横切带组织；A / B / C 是同一份能力数据的角色投影，用 P1–P4 表达深度，而不是用归属表达重要性。Harness 作为横切镜头单独展开。真实岗位经常混合这些责任，尤其是 Harness、平台架构师与负责人岗。

先读这五条

01 · 评测是工程，不是刷榜

15/25 岗提及评测，但原文要的是任务集、badcase 归因、回归和线上闭环。能读懂一条失败轨迹，比会背一个榜单分数更值钱。

02 · Harness 是组织，不是包装

它把模型、工具、上下文、状态、执行环境和反馈组织成可交付行为。模型是外部常数；Harness 是多数应用团队真正能控制的变量。

03 · 平台交付制品，Agentic 交付行为

平台的成功单位是「第 N 个团队仍能稳定运行」；Agentic 的成功单位是「真实任务分布上的完成率与成本」。两者接口必须显式。

04 · 传统能力是入场券，不是差异化

契约、幂等、隔离、可观测、多租户仍然有效。真正稀缺的是非确定性调试、语义正确性判定和每成功任务成本。

05 · 模型系统与 RL 是相邻专业

推理服务、后训练与 Agentic RL 不应被塞进平台树，也不能从全景消失。理解接口与成本，按岗位选择深度。

使用方式

自查节点 → 对岗选树 → 做出制品。不要按「读完」验收，按「能拿出证据」验收。

A · Agent Platform Engineering

让 Agent 可运行、可隔离、可恢复、可治理、可度量。主责执行环境、任务运行时、协议网关、平台控制面、身份策略、可观测和评测基础设施。

B · Agentic AI Engineering

让 Agent 在目标任务上有效、可靠、经济、可迭代。主责任务建模、模型与策略选择、上下文与记忆、工具语义、质量科学、产品行为和反馈闭环。

C · Adjacent Specializations

模型服务与推理、后训练与 Agentic RL、产品及组织领导力。它们不是附属知识；在对应岗位中就是主战场，但不需要每位平台工程师都达到同等深度。

03·5 / CAPABILITY GRAPH

域是主键，角色只是投影

上一节的分层视图回答「能力在系统哪里」，本节回答「能力本身怎么组织」。这两件事需要分开：分层是运行时拓扑，会随架构演进；能力域是知识结构，稳定得多。全图只维护一份能力数据，角色轨道（A/B/C）是从它派生出来的阅读投影。

分类学结论：A / B / C 保留，但降级为角色投影，不再作为根节点。根节点改为能力域：9 个域 + 1 个横切带。原因不是「两分法错」，而是它把三种不同的轴压在了同一层——岗位角色（A/B）、系统责任（分层）、专业成熟度（「相邻」暗含次要）。一旦需要新增方向，这种结构就只能在「再加一棵树」和「塞进现有树」之间二选一。

为什么保留 A/B/C，但不把它当根节点

问题具体现象本图处理
混轴A / B 是岗位角色，C 是「相邻」，同一层级用了两种划分标准。角色降为投影；根节点改为能力域，角色以深度列出现在覆盖矩阵中。
共管被拆散工具契约（A3）与工具语义（B5）本来是同一条链，却被分到两棵树里，读者要来回跳。领域视图把两者放回「互操作与契约」这一个域，共管关系直接可见。
深度被误读「相邻」听起来次要，但 C1 模型服务、C2 后训练在对应岗位上就是主战场。用 P1–P4 表达深度，而不是用归属表达重要性；同一分支对不同角色给不同目标等级。
技术绑在能力上框架与协议名每年变化，写在能力节点里会让整棵树快速过期。能力节点保持稳定；技术项进入独立登记册，标注类型与状态，可整体替换。

研究依据与本图的取舍

选型标准：能否把「稳定的能力」与「易变的实现」分开；能否容纳治理与生命周期；能否表达深度而不是只表达归属。

一个方法论上的取舍：本图没有采用任何单一的「权威分类标准」，因为没有。平台工程、AI 治理、技能框架各自只覆盖一部分。可复用的是结构原则——稳定层与易变层分离、治理横切、深度而非归属——而不是某份清单本身。

五级节点模型：森林 → 树 → 枝 → 叶 → 叶脉

同一棵树上，越往下越具体、越易变、越需要一线判断。层级的存在意义是让你知道「该在哪一层做决策」。

层级数量半衰期例子维护者
L1 域 Domain · 森林9 + 1 横切5–10 年执行与隔离、上下文与知识、模型系统架构负责人
L2 分支 Branch · 树183–5 年不受信执行与环境（A1）方向 owner
L3 能力 Capability · 枝752–4 年威胁模型与隔离分级团队 tech lead
L4 实践 Practice · 叶每节点 3–5 条1–2 年出口默认拒绝、凭证代理、按序列判定权限一线工程师
L5 技术项 Technology · 叶脉—6–18 个月Firecracker / gVisor / Kata / Temporal平台或基础设施团队
为什么把技术项单独拿出来：换掉叶脉不会让叶子消失，但会决定它还能不能活。技术项是可替换的导管——它支撑能力，却不应定义能力。把 Firecracker 写进能力节点的那一刻，这棵树就开始过期了。

深度刻度：同一分支，不同角色要求不同的深度

P1 · 认知

能解释术语与边界，能读懂他人的设计与产出，不独立决策。用来避免「不知道自己不知道」。

P2 · 会用

能在指导下完成实现，能验收常规产出；遇到无先例的问题知道该找谁升级。

P3 · 主责

能独立设计、交付与运维，能定义验收标准，能处理跨团队的接口与冲突。

P4 · 权威

能制定标准与取舍框架，能处理无先例问题，能培养 P3，并对组织级接口负责。

这张表回答一个常见争议：为什么「加个网关」不能解决 Agent 的权限问题——因为权限判断需要行动序列，而序列只有控制面看得到。

自治等级视图：按后果选自治，而不是按技术选自治

等级越高，能力要求与治理成本同时上升。多数生产系统应该停在 R2——不是因为技术不够，而是因为 R3 的恢复演练和值班成本往往超过收益。

等级决策自由度必须具备治理要求不该使用
R0 固定工作流无模型决策，模型只做单步生成确定性编排、结构化输出、校验常规发布与抽检输入分布稳定、规则可枚举时，加循环只会更差
R1 模型辅助模型建议，人执行输出契约、可解释性、错误回退输出抽检与责任归属需要多步工具调用才能完成任务
R2 有界 Agent工具循环 + 预算 + 审批门终止条件、幂等、审批、trace、回放关键动作人工确认、失败告警副作用不可逆且没有审批设计
R3 长任务自治跨会话、可恢复、可接管检查点、恢复演练、预算、人工接管、对账值班、事故响应、定期演练没有恢复演练、没有明确 owner
R4 多 Agent / 持续运行委派、并行、长期记忆、自触发协调成本测量、隔离、记忆治理、全局预算组织级审计、退出机制、模型升级回归单 Agent 尚未证明上下文或并行是瓶颈
一个反直觉的结论：自治等级是产品与风险决策，不是技术成熟度奖励。把 R3 降回 R2 常常是工程进步：预算、审批和恢复语义带来的确定性，比「全自动」更有价值。
03·7 / HARNESS LENS

Harness：把模型能力组织成可交付行为

Harness 不是某个框架，也不是 Prompt wrapper，而是「从目标到最终环境状态」的运行时组织。它把模型、工具、上下文、状态、执行环境和反馈组织成可交付行为。

一句话：模型决定「可能做什么」，Harness 决定「这次实际做什么、做完没有、失败怎么办」。对多数应用团队，模型是外部依赖，Harness 才是可控制、可评测、可迭代的工程对象。

01 · Loop & termination

目标、计划、行动、观察、停止条件、预算与人工接管。主责 B；运行时执行点由 A 提供。

B 制品：循环策略 + 终止原因 + 运行清单

02 · Model & prompt contract

模型选择、指令层级、结构化输出、模型路由与版本。主责 B；推理服务与容量由 C1 提供。

B 制品：模型/Prompt manifest + 输出契约

03 · Tools & skills

工具语义、Schema、Skill、MCP、A2A、注册、鉴权、版本与供应链。A 主契约与网关，B 主可用性。

A + B 制品：工具契约 + Skill 包 + 权限策略

04 · Context & memory

写、选、压、隔离；工作态、长期记忆、检索和用户纠正。A 主存储与租户，B 主写什么与选什么。

A + B 制品：上下文预算 + 记忆模式 + 删除路径

05 · Execution & recovery

沙箱、文件系统、浏览器、检查点、幂等、重试、暂停、恢复与销毁。

A 制品：隔离环境 + 恢复演练 + 副作用台账

06 · Eval & telemetry

任务集、轨迹、最终状态、评分器、重复试验、线上反馈和发布门禁。

A + B 制品：评测报告 + 可回放 trace + 回归门禁

Harness 的失效面与责任归属

失效面典型症状主责先做哪个制品
循环不收敛重复调用、预算耗尽、做完了还在做，或永远不结束。B2 / A2步数上限、循环检测、预算、终止原因与取消传播。
任务假成功回答声称完成，但数据库、文件或外部系统没有正确最终状态。B6最终状态断言优先于文本评分；轨迹与 outcome 分开评。
恢复重复副作用进程崩溃后重试，重复发信、扣款、写单或调用外部 API。A2幂等键、事务边界、outbox/inbox、记录回放与人工对账。
注入与数据外泄网页、工具描述或检索文档中的指令改变目标；敏感数据被带出。A1 / A5威胁模型、默认拒绝出口、凭证代理、关键路径红队测试。
模型升级回归换模型或 Prompt 后，行为、工具选择、成本或安全边界漂移。A5 / A7 / B6固定模型/Prompt/工具 manifest，灰度比较，过评测门禁再放量。
Harness is not a framework: LangGraph、OpenAI Agents SDK、Claude Agent SDK、ADK 等是实现选择；Harness 的验收面是可观察的任务行为，不是你是否用了某个图、某个角色或某个中间件。先把行为与失败面写清楚，再选实现。
04 / ROLE PROJECTION · A

Agent Platform Engineering

平台不是把传统微服务换成 Agent 名称。新增难点是：模型参与控制流、执行不受信动作、轨迹成为调试对象、质量与成本共同进入发布门禁。

这是同一张能力图的角色投影：每个分支右上角标注所属领域（D0–D9）。同一分支在其他角色下的目标深度，见 03·5 覆盖矩阵。

05 / ROLE PROJECTION · B

Agentic AI Engineering

Agentic 工程不是 Prompt 编写。核心是把开放任务转化为可约束的决策系统，并用轨迹、实验和产品信号持续证明系统是否变好。

两个相邻专业（C1 模型服务、C2 后训练）在这一轨道是 P2 深度：需要能定义接口与验收，但不需要自己训练模型。

06 / ROLE PROJECTION · C

相邻专业：全景中不可缺失的三块

这些方向可作为独立职业路径。平台或 Agentic 工程师至少需要理解其接口、成本与质量约束，但不必全部深入实现。

「相邻」描述的是与 A/B 的接口距离，不是重要性。在 C1、C2、C3 各自的岗位上，对应分支就是 P4 主战场。

保真度是旧经验可直接复用的程度，不是能力等级：高 可立即复用；中 需要重新设计边界；低 必须从零建立肌肉记忆。

传统 SWE 能力Agent 时代的对应物保真度你必须重学的那部分

OpenAPI 契约治理Tool Schema 治理高版本与弃用要考虑模型可能缓存旧 schema；危险工具需要默认审批标记。

工作流引擎 / MQDurable Agent Runtime中DAG 不能完全预编译——下一步由模型决定；引擎要支持运行中改变计划。
容器 / K8s 编排microVM / 沙箱编排高威胁模型从「你写的可信代码」变成「别人写的敌意代码」；共享内核不再是默认假设。

性能优化质量 / 时延 / 成本三维优化低三者互相拉扯；成本单位是 token、工具和执行时长，失败任务照样烧钱。

灰度发布灰度 + 模型版本回归中换模型等于换了一个不确定的上游依赖，行为漂移只能靠 eval 捕获，不能靠 diff。
多租户 SaaS多租户 Agent 平台高新增两条租户边界：记忆的内存边界、凭证的注入边界。串一次就是事故。
编译期类型检查结构化输出 + 校验 / 修复回合中校验发生在运行时；失败不是抛异常，而是要设计一个可观测、可停止的修复回合。
前端状态机流式 UI + 可中断交互中用户可能中途改主意、断连、反悔；Agent 要能接住并保留现场，而不是从头再来。

高保真迁移与必须新增的直觉

可以直接复用

API/Schema 契约、幂等键、事件溯源、事务与补偿、IAM/OBO、限流配额、分布式追踪、缓存、灰度回滚、多租户、容量规划、SRE 事故响应。

必须新增

传统类比最容易误导的地方：传统服务也会静默返回业务错误，Agent 也会 P99 超时；差异不是「旧系统确定、新系统随机」这么简单，而是模型现在参与决策、工具路径和上下文构造，导致质量、成本与副作用都呈路径依赖。

面试信号：把 JD 原话翻译成你要拿出的证据

面试官通常不会问「你懂不懂 Agent」，而是用一句 JD 原话追问具体经历。按「问题 → 证据 → 节点」准备故事，比背概念有效。

JD 里的原话（节选）实际会问什么你要拿出的证据对应节点
「能基于 Trace、评测结果及用户反馈持续优化 Agent」讲一次你的 Agent 为什么失败，你怎么定位的一条具体 trace + 归因结论 + 修复后的回归数据A6 · B6
「让『越用越好』从口号变成机制」你的 badcase 怎么变成不重复犯badcase → 规则/技能 → 回归用例 的闭环样例B8 · B6
「保障长程 Agent 任务的稳定性与可恢复性」进程挂了、断连了、跑了六小时，怎么办检查点设计 + 幂等策略 + 恢复演练记录A2
「围绕容器、虚拟机或轻量级 Sandbox 完善隔离」为什么不用普通容器，逃逸你怎么防选型三轴论证 + 一次红队验证结果A1
「把业务约束转化为可执行规则、把任务状态转化为过程制品」你怎么把一句模糊需求变成可执行的东西一份规格或状态机设计，附落地效果B2 · B7
「在信息保真与成本之间取得平衡」上下文快满了你怎么处理，压掉了什么压缩策略前后成功率、时延与成本对比B3
「把模型、工具、存储等外部依赖抽象为插件，实现热插拔」你怎么让换模型/换工具不改业务代码一层抽象的设计与它的泄漏点A3 · A4
「技能注册、版本管理、权限控制、调用契约」一千个工具塞给模型，怎么不乱检索式工具加载 + 权限围栏的设计A3 · B5

08 / MATURITY & PORTFOLIO

用可复核证据定义成熟度

T1 · EXPLAIN

能画出一次任务的模型、工具、状态、身份、轨迹与副作用；知道 MCP、A2A、Skills、Runtime、Memory 和 Eval 各自解决什么。

T2 · BUILD

做出单 Agent 纵切片：有结构化工具、持久化、人工接管、基础追踪和任务集；不是只有聊天 UI。

T3 · OPERATE

能处理重试风暴、重复副作用、上下文膨胀、模型变更、注入攻击和成本异常；用实验和线上信号共同判断质量。

T4 · LEAD

定义跨团队接口、风险分级、投资优先级和组织责任；能证明为何采用或不采用多 Agent、自研平台或后训练。

12–16 周参考路线：每阶段产生可检查制品

W01–02

W03–04

W05–07
持久化、隔离与恢复实现幂等、检查点、超时/预算、沙箱、出口控制。分别演示崩溃恢复、记录回放与实时重跑，不混称确定性。制品：故障演练报告。
W08–10
上下文与质量实验比较上下文/记忆策略、模型或 Harness 配置；固定版本，重复试验，报告均值、pass@1/pass^k（按需）、置信区间、成本和延迟。制品：实验报告 + 原始结果。
W11–12
生产信任与发布加入 OBO、序列策略、租户隔离、红队、灰度与回滚。门槛由业务风险决定。制品：威胁模型 + 发布门禁 + 回滚演练。
W13–16
按方向专精平台选 A1/A2；Agentic 选 B2/B4/B7；模型系统选 C1；研究选 C2；负责人选 C3。制品：一次有基线、有反证、有「不采用」结论的架构决策。

有容器就有安全边界从威胁模型选择隔离、出口、凭证和策略；对高风险不受信代码单独评估 microVM/VM。
有 Checkpoint 就能确定性回放区分状态恢复、记录回放和实时重跑；记录模型/工具 I/O 并处理外部副作用。
LLM Judge 上线即可信用人工标注校准，报告一致性和偏差，定期抽检并防止被评分器投机。
只压每次调用 token 单价优化每成功任务总成本：模型、重试、工具、沙箱、存储、网络、人工复核与失败损失。
把「不采用」当技术失败有实验依据地不采用多 Agent、长期记忆、自研框架或后训练，往往是最成熟的架构结论。

技术登记册：叶脉层，可整体替换

能力节点回答「要会什么」，登记册回答「现在用什么」。技术项不是能力的定义，而是当前可用的实现；它们每 6–18 个月就会换一批，所以单独放一页，标注类型与状态，而不是写进能力树里。

怎么用这一页：先用节点编号（A1、B6…）定位能力，再看这一行有哪些实现可选，最后用状态列判断它还能信多久。S0 稳定 表示接口与语义已收敛；S1 演进 表示仍在快速变化，必须固定版本；S2 易变 表示规范或生态近期有结构性变更。
